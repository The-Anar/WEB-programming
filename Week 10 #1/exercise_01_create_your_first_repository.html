Exercise 01 — Create Your First Repository

Practice the basic Git workflow by creating a project, initializing Git, tracking files, and saving your first commits.

BATSUREN ANAR · STUDENT ID: 202637018

Exercise Overview

In this exercise, you will create a small website project and use Git to track its development.

Objective

Create your first local Git repository and save changes with commits.

Tools

Visual Studio Code, a terminal, Git, and a web browser.

Final Result

A website project with a Git history containing at least five meaningful commits.

Part 01 — Create Your Project Folder

TASK 01

First, create a new folder for your portfolio project. You can do this in VS Code or through the terminal.

Terminal Commands

mkdir portfolio
cd portfolio

mkdir creates a new folder. cd moves into that folder.

Open this folder in VS Code before continuing.

Part 02 — Initialize Git

TASK 02

Initialize a Git repository inside your project folder. 

git init

Git creates a hidden .git directory. This directory stores the repository's history and configuration.

Check the repository status: 

git status

You should see information about your new repository.

Part 03 — Create Your Homepage

TASK 03

Create a file named index.html in your portfolio folder.

Add the following basic HTML structure: 

<!doctype html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My Portfolio</title>
</head>
<body>
    <h1>Hello, I'm Anar!</h1>
    <p>Welcome to my portfolio website.</p>
</body>
</html>

Save the file. You now have your first project file.

Part 04 — Check the Repository Status

TASK 04

Run the following command: 

git status

Git should show index.html as an untracked file. This means Git sees the file, but it is not yet being tracked.

Important Concept

An untracked file is a file that exists in your project directory but has not yet been added to Git's tracking system.

Part 05 — Stage Your File

TASK 05

Add index.html to the staging area. 

git add index.html

Then check the status again: 

git status

The file should now appear as a new file ready to be committed.

Part 06 — Create Your First Commit

TASK 06

Save the staged file as your first commit. 

git commit -m "Initial commit: add homepage"

A commit is a snapshot of your staged changes. The message explains what the commit contains.

Check Your Commit History

git log --oneline

You should see your first commit in the history.

Part 07 — Make More Changes

TASK 07

Add more information to your homepage. For example, add an About section. 

<section>
    <h2>About Me</h2>
    <p>I am a Computer Engineering student
    learning web development.</p>
</section>

Save your changes, then stage and commit them: 

git add index.html
git commit -m "Add about section"

Part 08 — Create More Meaningful Commits

TASK 08

Continue improving your portfolio. Make separate commits for meaningful changes.

Example Commit Plan

  1. Initial commit: add homepage
  2. Add about section
  3. Add profile photo
  4. Add skills section
  5. Add project links

Your repository should contain at least five meaningful commits.

Each commit should represent a real change. Do not create empty commits just to increase the count.

Part 09 — Review Your Work

TASK 09

Use these commands to check your project and history: 

# Check repository status
git status

# View all commits
git log

# View compact commit history
git log --oneline

# Review unstaged changes
git diff

If all your changes have been committed, git status should report that the working tree is clean.

Submission Checklist

Before finishing, make sure your portfolio includes:

  • A homepage named index.html.
  • Your name and a short introduction.
  • A profile photo.
  • A skills section.
  • Links to two or three projects.
  • At least five meaningful Git commits.

Exercise Summary

  • Create a project folder.
  • Initialize Git using git init.
  • Create your index.html homepage.
  • Stage files using git add.
  • Save snapshots using git commit.
  • Review your history using git log.
  • Build a project history with at least five meaningful commits.

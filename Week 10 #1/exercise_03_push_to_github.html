Exercise 03 — Push to GitHub

Connect your local Git repository to GitHub, upload your commits, and learn how to synchronize your local project with a remote repository.

BATSUREN ANAR · STUDENT ID: 202637018

Exercise Overview

Git stores commits on your computer. GitHub hosts repositories online. In this exercise, you will connect the two and push your local project to GitHub.

Local Repository

Your project and its Git commit history stored on your computer.

Remote Repository

An online copy of your project hosted on GitHub.

Goal

Upload local commits and verify that your files appear on GitHub.

Part 01 — Prepare Your Local Repository

TASK 01

Open the project you created in Exercise 01. Make sure it is already a Git repository.

Check its status:

git status
git log --oneline

If you have uncommitted changes, stage and commit them before continuing: 

git add .
git commit -m "Update portfolio content"

If there are no new changes, Git may tell you that your working tree is clean. That is okay.

Part 02 — Create a GitHub Repository

TASK 02

Open GitHub and sign in to your account.

  1. Click the + button near the top-right corner.
  2. Select New repository.
  3. Enter a repository name, such as portfolio.
  4. Choose Public or Private.
  5. For this exercise, leave the README, .gitignore, and license unchecked if your local project already has files.
  6. Click Create repository.

Important

You are connecting an existing local project. Creating a README on GitHub at this stage can create a separate initial commit and make the first push more complicated.

Part 03 — Copy the Repository URL

TASK 03

After creating the repository, GitHub displays a page with instructions for connecting an existing repository.

  1. Find the repository's HTTPS URL.
  2. Copy the URL.
  3. Keep it ready for the next command.

Example URL format:

https://github.com/YOUR-USERNAME/portfolio.git

Replace YOUR-USERNAME with your actual GitHub username. Do not type this example URL literally.

Part 04 — Connect Local Git to GitHub

TASK 04

Return to the terminal inside your local project folder. Add GitHub as the remote repository named origin. 

git remote add origin https://github.com/YOUR-USERNAME/portfolio.git

Replace the example URL with the URL you copied from GitHub.

Check the remote connection:

git remote -v

You should see the GitHub URL listed for fetch and push.

Part 05 — Push Your Commits

TASK 05

Upload your local commits to GitHub: 

git push -u origin main

This command pushes the local main branch to the remote repository named origin.

What does -u mean?

The -u option sets the upstream relationship between your local branch and the remote branch.

After this first push, you can usually use the shorter command: 

git push

If your branch is named master instead of main, use git push -u origin master.

Part 06 — Verify Your GitHub Repository

TASK 06

Open your GitHub repository in a browser and check:

  • Your project files are visible.
  • Your index.html file appears.
  • Your commit history is available.
  • Your latest commit message is displayed.

Local vs Remote

      |
      | git push
      v
GITHUB REMOTE REPOSITORY

Push sends your local commits to the remote repository.

Part 07 — Make Another Change and Push Again

TASK 07

Open index.html and add a new line to your portfolio, such as: 

<p>I am continuously improving my web development skills.</p>

Save the file, then run:

git status
git add index.html
git commit -m "Update portfolio introduction"
git push

Refresh your GitHub repository. The new commit and updated file should appear.

Part 08 — Understand Pull

TASK 08

Push sends your local commits to GitHub. Pull brings remote changes into your local branch. 

git pull origin main

This command fetches changes from the remote main branch and integrates them into your current local branch.

Remember the Difference

git push

Local commits → GitHub

git pull

GitHub changes → Local branch

git clone

Copies a remote repository to your computer.

Common Problems

Problem 1 — Authentication Required

GitHub may ask you to authenticate. Follow the sign-in process shown by Git Credential Manager or your configured authentication method.

Problem 2 — Remote Already Exists

If you see an error saying origin already exists, check the existing remote: 

git remote -v

If the URL is incorrect, update it: 

git remote set-url origin YOUR-REPOSITORY-URL

Problem 3 — Push Rejected

The remote repository may contain commits that your local branch does not have.

First, inspect the situation. If the histories are compatible, you may need to pull and integrate the remote changes before pushing again: 

git pull origin main
git push

Do not use force push as a first solution. It can overwrite remote history.

Complete Command Sequence

# Check local repository
git status
git log --oneline

# Connect GitHub repository
git remote add origin YOUR-REPOSITORY-URL

# Check remote
git remote -v

# First push
git push -u origin main

# After making another change
git add .
git commit -m "Update portfolio"
git push

Submission Checklist

  • Create a GitHub repository named portfolio.
  • Connect your local repository using git remote add origin.
  • Verify the remote using git remote -v.
  • Push your main branch to GitHub.
  • Confirm your files appear online.
  • Make another meaningful change.
  • Commit and push the new change.
  • Verify the latest commit on GitHub.

Exercise Summary

  • Git stores your project history locally.
  • GitHub hosts your repository online.
  • git remote add origin connects a remote repository.
  • git push uploads local commits.
  • git pull fetches and integrates remote changes.
  • git clone copies a remote repository locally.

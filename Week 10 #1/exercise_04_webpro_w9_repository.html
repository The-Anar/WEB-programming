Exercise 04 — WebPro W9 Repository

Create a public GitHub repository, upload your HTML file, configure GitHub Pages, and publish your website online.

BATSUREN ANAR · STUDENT ID: 202637018

Exercise Overview

In this exercise, you will publish a simple website using Git and GitHub. You will create a repository named webpro-w9, push your first commit, and enable GitHub Pages.

Repository

Create a public GitHub repository named webpro-w9.

Git Workflow

Initialize, configure, stage, commit, and push your project.

Publication

Enable GitHub Pages and verify your published website.

Part 01 — Create a GitHub Repository

TASK 01
  1. Open GitHub.
  2. Sign in to your account.
  3. Click the + button.
  4. Select New repository.
  5. Enter the repository name: webpro-w9.
  6. Set the repository visibility to Public.
  7. Leave the README, .gitignore, and license unchecked.
  8. Click Create repository.

Repository Information

Repository name: webpro-w9
Visibility: Public
README: Unchecked
.gitignore: Unchecked
License: Unchecked

We are creating the repository online first, then connecting it to a new local Git repository.

Part 02 — Create Your Local Project

TASK 02

Open VS Code and open a terminal. Create a project folder: 

mkdir webpro-w9
cd webpro-w9

Create a file named index.html. Add the following HTML: 

<!doctype html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Web Programming Week 9</title>
</head>
<body>
    <h1>Web Programming Week 9</h1>

    <p>Name: Batsuren Anar</p>

    <p>Date: November 20, 2026</p>
</body>
</html>

Save the file. Make sure the name is exactly index.html.

The date above is an example for this exercise. Change it if your instructor requires the actual submission date.

Part 03 — Initialize Git on Main

TASK 03

Initialize the repository and explicitly create the main branch: 

git init -b main

The -b main option sets the initial branch name to main.

Why use this command?

It avoids accidentally creating a branch named master when the instructions expect main.

Check your branch: 

git branch

Part 04 — Configure Your Git Identity

TASK 04

Git records the author name and email in your commits. Configure them using your own information: 

git config --global user.name "Batsuren Anar"
git config --global user.email "YOUR-GITHUB-EMAIL"

Replace YOUR-GITHUB-EMAIL with the email address associated with your GitHub account, or an email address GitHub recognizes for your commits.

Verify your configuration:

git config --global user.name
git config --global user.email

These settings identify the author of your commits. They do not log you in to GitHub.

Part 05 — Stage and Commit index.html

TASK 05

Check the repository status: 

git status

Stage your HTML file: 

git add index.html

Create your first commit: 

git commit -m "Add Week 9 index page"

Review your commit: 

git log --oneline

Remember

git add stages your changes. git commit saves a snapshot in your local repository.

Your commit is still local. You have not uploaded it to GitHub yet.

Part 06 — Connect to GitHub

TASK 06

Open your GitHub repository named webpro-w9.

Copy its HTTPS URL. It should look similar to: 

https://github.com/YOUR-USERNAME/webpro-w9.git

Add the remote repository: 

git remote add origin https://github.com/YOUR-USERNAME/webpro-w9.git

Replace the example URL with your actual repository URL.

Verify the connection:

git remote -v

Part 07 — Push to GitHub

TASK 07

Upload your local main branch: 

git push -u origin main

This sends your local commits to the GitHub repository and sets the upstream branch.

Verify the Upload

  1. Refresh your GitHub repository page.
  2. Find index.html in the file list.
  3. Open the file.
  4. Check that your name and date appear.
  5. Check that your commit message is visible.

Part 08 — Enable GitHub Pages

TASK 08

GitHub Pages can publish your repository as a website.

  1. Open your webpro-w9 repository on GitHub.
  2. Click Settings.
  3. Find Pages in the left sidebar.
  4. Under Build and deployment, find Source.
  5. Select Deploy from a branch.
  6. Under Branch, select main.
  7. Select the / (root) folder.
  8. Click Save.

GitHub Pages Settings

Source: Deploy from a branch

Branch: main
Folder: / (root)

GitHub will start building and publishing your website.

Part 09 — Verify Your Published Website

TASK 09

After GitHub Pages finishes publishing, GitHub will display a website URL in the Pages settings.

The URL usually follows this format: 

https://YOUR-USERNAME.github.io/webpro-w9/

Replace YOUR-USERNAME with your GitHub username.

Final Verification

  • Open the published URL in your browser.
  • Confirm the page loads successfully.
  • Check the page title.
  • Confirm your name appears.
  • Confirm the date appears.

The first publication may take a few minutes. If the page is not ready immediately, check the Pages settings again and wait for deployment.

Complete Command Sequence

The following commands summarize the local Git workflow. Replace the example email and repository URL with your own. 

# Create and open project folder
mkdir webpro-w9
cd webpro-w9

# Initialize main branch
git init -b main

# Configure Git identity
git config --global user.name "Batsuren Anar"
git config --global user.email "YOUR-GITHUB-EMAIL"

# Stage and commit
git add index.html
git commit -m "Add Week 9 index page"

# Connect GitHub
git remote add origin YOUR-REPOSITORY-URL

# Upload the commit
git push -u origin main

Common Problems

Problem 1 — src refspec main does not match any

This can happen if your local branch is not named main, or if you have not created your first commit.

Check your branch:

git branch

Check whether you have a commit: 

git log --oneline

Make sure you have staged and committed at least one file before pushing.

Problem 2 — origin already exists

Check the current remote: 

git remote -v

If the URL is wrong, update it: 

git remote set-url origin YOUR-REPOSITORY-URL

Problem 3 — GitHub Pages shows a 404 page

  • Check that the repository is public.
  • Check that index.html is in the root folder.
  • Check that Pages uses the main branch.
  • Check that the selected folder is / (root).
  • Wait for deployment to finish.

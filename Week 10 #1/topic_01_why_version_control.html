Topic 01 — Why Version Control

Track changes, save project history, restore previous versions, and collaborate with other developers without losing work.

What Is Version Control?

Version control is a system that records changes made to files over time. It allows developers to see how a project has changed, review previous versions, and recover earlier work.

Instead of manually saving many copies of the same project, developers use version control to maintain an organized history of their work.

Why Do Developers Need Version Control?

01. Track Changes

Record modifications to files and understand what was added, removed, or updated.

02. Save Snapshots

Save important states of a project so its development history is organized.

03. Rollback

Return to an earlier version when a new change causes problems.

04. Collaboration

Allow multiple developers to contribute to the same project and share their work.

05. Project History

Understand how a project developed from its beginning to its current state.

06. Safer Development

Reduce the risk of permanently losing useful work when experimenting with code.

The Problem Without Version Control

Imagine building a website and manually creating a new file every time you make an improvement.

Example: Multiple file copies

my-website/
├── index.html
├── index-final.html
├── index-final-new.html
├── index-final-updated.html
└── index-final-actually-final.html

This becomes confusing because it is difficult to identify the correct version and understand exactly what changed between files.

Problems with this approach

  • Too many duplicate files.
  • Unclear project history.
  • Difficulty identifying the latest version.
  • Risk of accidentally deleting important work.
  • Difficulty coordinating changes with teammates.

How Version Control Organizes Changes

Version control records meaningful points in a project's development. In Git, these saved records are called commits.

Version 1 — Create Homepage

The first version of the website is created.

Version 2 — Add Navigation

A navigation menu is added to help visitors move around the website.

Version 3 — Improve Design

CSS styling, colors, and spacing are improved.

Version 4 — Fix Mobile Layout

The website is adjusted to work better on smaller screens.

What Is a Snapshot?

A snapshot represents a saved state of a project at a particular point in its development.

In Git, a commit records a set of changes in the repository's history. Developers can use commits to understand and review earlier work.

Example of a project history

Commit 1: Initial commit
Commit 2: Add homepage
Commit 3: Add navigation menu
Commit 4: Improve page styling
Commit 5: Fix mobile layout

Each commit has a message describing the changes. This makes the development history easier to follow.

What Does Rollback Mean?

Rollback means returning a project or file to an earlier state when a newer change causes a problem.

Example scenario

Version 1: Website works correctly
       ↓
Version 2: New CSS is added
       ↓
Version 3: Layout becomes broken
       ↓
Review previous project history
       ↓
Recover a working version

Version control makes it easier to inspect earlier changes and recover from mistakes.

How Version Control Helps Collaboration

Software projects are often developed by teams. Different developers may work on different features and contribute changes to the same project.

Developer A

Works on the homepage and navigation menu.

Developer B

Works on the contact form and validation.

Shared Project

Their contributions can be combined into one project through a version control workflow.

Version control helps teams track who changed what and manage contributions more safely.

Introduction to Git

Git is a free and open-source version control system. It runs locally on your computer and tracks changes to project files.

Free and Open Source

Git is freely available and its source code can be inspected and improved by the community.

Local Version Control

Git manages project history directly on your computer.

Works Offline

You can perform local operations such as committing and viewing history without internet.

Example Git command

git init

This command initializes a new Git repository in the current project folder. We will practice this command in a later topic.

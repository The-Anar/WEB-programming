Topic 03 — The Git Workflow (3 Areas)

Learn how Git manages file changes through the Working Directory, Staging Area, and Local Repository.

Understanding the Git Workflow

Git uses three main areas to manage changes in a project. Each area has a different purpose, and files move between them as you work.

The three areas are:

  1. Working Directory
  2. Staging Area
  3. Local Repository

The Three Areas

01. Working Directory

This is the folder where you create, edit, and delete project files.

Changes made here are not yet staged or saved in a commit.

Example

index.html

You edit the homepage in VS Code.

02. Staging Area

The staging area is where you select which changes should be included in your next commit.

You use git add to move changes into this area.

Example 
git add index.html

The homepage is ready to be committed.

03. Local Repository

The local repository stores your saved commits and project history.

You use git commit to save staged changes as a snapshot.

Example 
git commit -m "Add homepage"

Your changes are now recorded in Git history.

How Files Move Through Git

A typical Git workflow moves changes through these three areas in order.

01 Working Directory

Edit files

02 Staging Area

git add

03 Local Repository

git commit

04 Remote Repository

git push

The remote repository, such as GitHub, is an additional destination outside the three main local Git areas.

Important Git Commands

Check the current project status

git status

Shows which files are modified, staged, or untracked.

Stage one file

git add index.html

Adds changes from index.html to the staging area.

Stage all changes

git add .

Stages all changes in the current directory and its subdirectories.

Save a commit

git commit -m "Add homepage"

Saves the staged changes as a new commit in the local repository.

Complete Workflow Example

Imagine you are creating a personal portfolio. You create an HTML file, stage it, and commit it. 

# Check the project status
git status

# Stage the homepage
git add index.html

# Save the changes
git commit -m "Add portfolio homepage"

# Upload the commit to GitHub
git push

The first three commands work with your local Git repository. The final command sends commits to a remote repository.

Remember

  • Working Directory: where you edit files.
  • Staging Area: where you select changes for the next commit.
  • Local Repository: where commits and project history are stored.
  • git add stages changes.
  • git commit saves staged changes locally.
  • git push uploads local commits to a remote repository.

Topic 04 — Init, Status, Add & Commit

Learn the essential Git commands used to create a repository, check file changes, stage files, and save commits.

Starting a Git Repository

Before Git can track changes in a project, you need to initialize a Git repository.

The git init command creates a new Git repository in your current project folder. Git uses a hidden .git directory to store repository information and history. 

git init

Run this command inside the folder you want Git to track.

Four Essential Commands

01. git init

Initializes a new Git repository in the current directory. 

git init

02. git status

Displays the current state of your working directory and staging area. 

git status

03. git add

Selects file changes and places them in the staging area. 

git add index.html

04. git commit

Saves staged changes as a snapshot in your local Git history. 

git commit -m "Add homepage"

Step 1 — Initialize the Repository

Open your terminal in your project folder. Run git init to start tracking the project with Git. 

mkdir my-portfolio
cd my-portfolio
git init

Explanation:

  • mkdir my-portfolio creates a folder.
  • cd my-portfolio enters the folder.
  • git init initializes Git in that folder.

Step 2 — Check Repository Status

Use git status to see which files Git is tracking and which files have changes. 

git status

Git can show:

  • Untracked files that Git has not started tracking.
  • Modified files that have changed.
  • Staged changes ready to be committed.
  • Whether your working directory is clean.

Step 3 — Add Files to the Staging Area

Before making a commit, you must select which changes should be included.

Add one specific file

git add index.html

Stages changes from index.html.

Add all changes

git add .

Stages all changes in the current directory and its subdirectories.

You can use git status again to confirm which files are staged.

Step 4 — Commit Your Changes

A commit saves the staged changes as a snapshot in your local repository. 

git commit -m "Initial commit: add index.html"

The message after -m describes what the commit contains.

Good Commit Messages

  • Add homepage
  • Fix navigation links
  • Update profile section
  • Add contact form

A good commit message is short, clear, and explains what changed.

Complete Example

This example creates a project, initializes Git, stages an HTML file, and saves the first commit. 

# Create and enter the project folder
mkdir my-portfolio
cd my-portfolio

# Initialize Git
git init

# Check repository status
git status

# Stage the homepage
git add index.html

# Save the first commit
git commit -m "Initial commit: add index.html"

# Check the status again
git status

After a successful commit, Git should report that there are no staged or unstaged changes if everything has been saved.

Important: Commit Does Not Mean Push

A commit saves your changes in your local repository. It does not automatically upload them to GitHub.

git commit

Saves a snapshot in your local Git repository. 

git commit -m "Add homepage"

git push

Uploads your local commits to a remote repository such as GitHub. 

git push

Remember

  • git init creates a new local repository.
  • git status shows the current state of files.
  • git add index.html stages one file.
  • git add . stages all changes in the current directory and its subdirectories.
  • git commit -m "message" saves staged changes locally.
  • A commit is not the same as pushing changes to GitHub.

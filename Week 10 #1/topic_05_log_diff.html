Topic 05 — Git Log & Diff

Learn how to inspect your project's commit history and compare changes between file versions using Git.

BATSUREN ANAR · STUDENT ID: 202637018

Why Review Git History?

Every time you make a commit, Git records a snapshot of your project. These commits create a history of how your project has changed.

Reviewing history helps you understand:

  • What changes were made.
  • When a change was recorded.
  • Who created a commit.
  • Which files were changed.
  • How the project developed over time.

01. Git Log

The git log command displays the commit history of a repository. 

git log

It shows information such as:

  • Commit hash — a unique identifier for a commit.
  • Author — the person who made the commit.
  • Date — when the commit was created.
  • Commit message — a description of the changes.

Example Git Log Output

commit a82f91c
Author: Anar
Date:   Wed Nov 18 14:30:00 2026

    Add contact section

commit 72bc410
Author: Anar
Date:   Tue Nov 17 10:15:00 2026

    Create homepage

This is an illustrative example. Your actual commit hashes, dates, and messages will be different.

02. Git Log --oneline

Sometimes the full log contains too much information. Use git log --oneline to display a shorter version of the commit history. 

git log --oneline

Example Output

a82f91c Add contact section
72bc410 Create homepage
3d9a6b2 Initial commit

Each line displays a short commit hash and its commit message.

03. Git Diff

The git diff command compares changes between versions of files. It helps you see exactly what was added or removed. 

git diff

By default, this shows differences between your working directory and the staging area.

Understanding Diff Symbols

+ Added Lines

Lines beginning with + represent added content.

- Removed Lines

Lines beginning with - represent removed content.

Context Lines

Lines without a plus or minus sign provide context around the changes.

Example: Comparing Changes

Imagine your original HTML file contained a simple heading.

Before

<h1>My Website</h1>

After

<h1>My Portfolio</h1>
<p>Welcome to my website.</p>

Example Git Diff

- <h1>My Website</h1>
+ <h1>My Portfolio</h1>
+ <p>Welcome to my website.</p>

The minus sign indicates the old heading was removed. The plus signs indicate the new content was added.

Useful Git History Commands

View complete history

git log

View compact history

git log --oneline

View unstaged changes

git diff

View staged changes

git diff --staged

Shows changes that are staged and ready to be included in the next commit.

Compare two commits

git diff commit1 commit2

Compares the differences between two commit references.

Practical Workflow

You can use Git history and comparison commands while working on a website. 

# Check the current changes
git status

# See what changed
git diff

# Stage the changes
git add .

# Review staged changes
git diff --staged

# Save the changes
git commit -m "Update portfolio content"

# Review commit history
git log --oneline

This workflow lets you inspect your changes before saving them and review the history afterward.

Remember

  • git log displays commit history.
  • git log --oneline displays a compact history.
  • git diff shows unstaged changes.
  • git diff --staged shows staged changes.
  • + represents added lines.
  • - represents removed lines.
  • Reviewing changes before committing helps prevent mistakes.

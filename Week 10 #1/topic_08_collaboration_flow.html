Topic 08 — Collaboration Flow

Learn how developers work together using Git and GitHub: Fork, Clone, Branch, Commit, Push, and Pull Request.

BATSUREN ANAR · STUDENT ID: 202637018

Why Do Developers Collaborate?

Software projects are often created by teams. Each developer may work on a different feature, fix bugs, or improve existing code.

Git tracks changes, while GitHub provides tools for sharing code and reviewing contributions. Together, they help developers work on the same project.

Share Code

Team members can access a shared project through a remote repository.

Review Changes

Developers can inspect and discuss changes before they are added to the main project.

Track Contributions

Git records commits so the team can see how the project has changed.

The GitHub Collaboration Workflow

A common workflow for contributing to another GitHub project is:

01. Fork

Create your own GitHub copy of someone else's repository.

02. Clone

Download your forked repository to your computer.

03. Branch

Create a separate branch for your changes.

04. Edit & Commit

Modify files, stage changes, and save commits.

05. Push

Upload your branch and commits to your GitHub fork.

06. Pull Request

Ask the original project maintainers to review and merge your changes.

01. Fork a Repository

A fork is your own GitHub copy of another user's repository. It allows you to make changes without directly modifying the original project.

  1. Open the original repository on GitHub.
  2. Click the Fork button.
  3. Select your GitHub account as the destination.
  4. GitHub creates a copy under your account.

Forking happens on GitHub, not through a normal local Git command.

02. Clone Your Fork

After forking, clone your repository to your computer. 

git clone https://github.com/your-username/project.git

This creates a local copy of your fork. You can now open the project and edit its files.

03. Create a Feature Branch

Before editing the project, create a separate branch for your contribution. 

git checkout -b feature/update-homepage

This creates a new branch and switches your working directory to it.

Keeping changes in a separate branch makes your work easier to review.

04. Edit and Commit Your Changes

Make your changes to the project files. Then stage and commit them. 

# Check changed files
git status

# Stage your changes
git add .

# Create a commit
git commit -m "Update homepage layout"

A commit records your changes in your local Git repository.

05. Push Your Branch to GitHub

Upload your local feature branch to your GitHub fork. 

git push -u origin feature/update-homepage

Your new branch and its commits are now available in your remote repository.

Here, origin usually refers to your forked GitHub repository.

06. Create a Pull Request

A Pull Request (PR) is a request to merge your proposed changes into another branch or repository.

  1. Open your repository on GitHub.
  2. Select your feature branch.
  3. Click Compare & pull request, if available.
  4. Choose the original repository and target branch.
  5. Write a clear title and description.
  6. Submit the Pull Request for review.

The project maintainers can review your code, leave comments, request changes, and decide whether to merge it.

Pull Request vs git pull

These two terms sound similar, but they have different meanings.

Pull Request

A GitHub feature used to propose changes and request a review and merge.

git pull

A Git command that downloads remote changes and integrates them into your current branch.

A Pull Request is a collaboration and review process. git pull is a command used in your local repository.

Understanding Merge Conflicts

A merge conflict happens when Git cannot automatically combine changes from different branches.

For example, two developers might edit the same lines of the same file differently.

Example Conflict Markers

<<<<<<< HEAD
<h1>Welcome to my portfolio</h1>
=======
<h1>Welcome to Anar's website</h1>
>>>>>>> feature/title

Git uses these markers to show the conflicting sections. You must edit the file and decide which content to keep.

How to Resolve a Conflict

  1. Open the file containing the conflict.
  2. Read both versions of the conflicting code.
  3. Edit the file to create the correct final version.
  4. Remove the conflict markers.
  5. Stage the resolved file with git add.
  6. Complete the merge with a commit if Git requires one.
git add index.html
git commit -m "Resolve merge conflict"

Do not leave conflict markers in your final code. If Git opened a merge process, follow its instructions to complete the merge.

Complete Collaboration Example

Here is a simplified command sequence for contributing to a project through a fork. 

# 1. Clone your fork
git clone https://github.com/your-username/project.git

# 2. Enter the project folder
cd project

# 3. Create a feature branch
git checkout -b feature/update-homepage

# 4. Stage and commit your changes
git add .
git commit -m "Update homepage"

# 5. Push the branch to your fork
git push -u origin feature/update-homepage

After pushing, open GitHub and create a Pull Request to propose your changes to the original project.

Remember

  • Fork: Create your own GitHub copy of another repository.
  • Clone: Download a repository to your computer.
  • Branch: Create a separate line of development.
  • Commit: Save a snapshot of your changes.
  • Push: Upload your commits to GitHub.
  • Pull Request: Propose changes for review and merging.
  • Merge conflict: Manually resolve changes Git cannot combine automatically.

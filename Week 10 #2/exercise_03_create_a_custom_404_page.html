Week 10.2 · Practice Exercise 03

Create a Custom 404 Page

Build a personalized error page that helps visitors understand missing pages and navigate back to my portfolio.

01. Objective

In the previous exercise, I tested a missing URL and examined GitHub Pages' default 404 error page.

In this exercise, I created my own 404.html page using HTML, CSS and JavaScript. I designed it to match my existing portfolio.

02. My Custom 404 Page

Instead of using a generic error page, I designed a custom page with my portfolio's visual identity.

🏠 Home　　📚 Coursework　　👤 About

Illustrative preview of my custom 404 page.

My design features

  • Large gold 404 error number.
  • Dark purple gradient hero section.
  • Light and dark theme toggle.
  • Home, Coursework and About navigation.
  • Three helpful destination cards.
  • Responsive layout for smaller screens.

04. CSS Design and Responsive Layout

I used CSS variables to support both light and dark themes. The page uses a purple gradient, rounded cards, borders and shadows to match my portfolio.

Responsive layout

@media (max-width: 650px) {
    .suggestions {
        grid-template-columns: 1fr;
    }

    .hero {
        padding: 42px 20px;
    }
}

On smaller screens, the three destination cards become a single column.

Accessibility

  • Accessible labels for navigation and the error message.
  • Visible keyboard focus styles.
  • Reduced-motion support.
  • Descriptive text for the error and navigation links.

05. JavaScript Theme Toggle

JavaScript allows visitors to switch between light and dark mode. The selected theme is saved in localStorage so it can be restored when the page is opened again in the same browser. 

function setTheme(isDark) {
    document.body.classList.toggle("dark-mode", isDark);

    themeIcon.textContent = isDark ? "☀️" : "🌙";
    themeLabel.textContent = isDark ? "Light mode" : "Dark mode";
}

06. Navigation Links

My 404 page provides links to useful parts of my main portfolio:

  • Home — returns to the main portfolio.
  • Coursework — opens the coursework section.
  • About — opens my About page.

Because my portfolio is published as a GitHub Pages project site, I use paths beginning with /WEB-programming/. 

<a href="/WEB-programming/index.html">
    Back to Main Portfolio
</a>

These paths belong to my main WEB-programming website. They should not be changed to the /webpro-w9/ path unless I am creating a separate 404 page for that repository.

07. Test the Custom 404 Page

After placing 404.html in the root of the publishing repository and deploying it, I can test it by opening a URL that does not exist.

Test my main portfolio's 404 page

Expected result:

  • My custom 404 design appears.
  • The theme toggle works.
  • The destination links navigate to the correct pages.
  • The page adapts to mobile screen sizes.

08. Conclusion

I created a custom 404 page that matches my portfolio design instead of relying on GitHub's generic error page.

Through this exercise, I practiced semantic HTML, CSS styling, responsive design, JavaScript, localStorage and accessibility.

Introduction to GitHub Actions

Learn how GitHub can automatically run tasks when changes are made to a repository.

BATSUREN ANAR · STUDENT ID: 202637018

01 · INTRODUCTION

What Are GitHub Actions?

GitHub Actions is an automation platform built into GitHub. It allows developers to automatically run tasks when certain events happen in a repository.

For example, a workflow can run when code is pushed to GitHub, when a pull request is opened, or when a scheduled event occurs.

Simple example

When you push new website files to the main branch, a workflow can automatically build and deploy the website.

02 · HOW IT WORKS

The Automation Process

1. Event

A repository event happens, such as pushing a commit.

2. Workflow

GitHub reads the workflow instructions from a YAML file.

3. Job and Steps

The workflow runs jobs containing individual steps.

4. Result

The task completes, and GitHub shows whether it succeeded or failed.

03 · WORKFLOW FILES

Where Are Workflows Stored?

GitHub Actions workflow files are written in YAML and stored inside the .github/workflows/ directory.

Example repository structure

portfolio/
├── index.html
├── style.css
└── .github/
    └── workflows/
        └── deploy.yml

The workflow file tells GitHub which events should trigger automation and what tasks to perform.

04 · YAML EXAMPLE

A Simple Workflow

The following example shows a workflow that runs whenever code is pushed to the main branch. 

name: Example Workflow

on:
  push:
    branches:
      - main

jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      - name: Print a message
        run: echo "Hello from GitHub Actions!"

This is an educational example. It runs a simple command rather than deploying a website.

05 · CI AND CD

What Do CI and CD Mean?

Continuous Integration (CI)

Automatically checks or tests code changes when developers push updates or open pull requests.

Continuous Deployment (CD)

Automatically publishes approved changes to a live environment.

Example workflow:

  1. A developer updates a website.
  2. The developer pushes changes to GitHub.
  3. Automated checks run.
  4. If deployment is configured, the website is published.

06 · WHY USE IT?

Benefits of Automation

  • Reduces repetitive manual work.
  • Helps detect problems early.
  • Makes testing more consistent.
  • Can automate website deployment.
  • Shows workflow results inside GitHub.

08 · SUMMARY

What I Learned

GitHub Actions automates tasks using workflows. Workflows are written in YAML and stored in the .github/workflows/ directory.

They can run tests, check code, and automate deployment. CI focuses on integrating and checking changes, while CD automates delivery or deployment.

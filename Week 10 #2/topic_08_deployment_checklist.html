WEEK 10.2 · TOPIC 08

Website Deployment Checklist

Review the important steps before publishing a website with GitHub Pages.

BATSUREN ANAR · STUDENT ID: 202637018

01 · INTRODUCTION

Why Use a Deployment Checklist?

Deploying a website involves more than uploading HTML files. Before publishing, developers should check the repository, website structure, links, accessibility, and final live version.

A checklist helps prevent common mistakes and makes the deployment process easier to repeat.

02 · BEFORE DEPLOYMENT

Prepare Your Website

Repository

  • Repository exists on GitHub.
  • Latest files are committed.
  • Changes are pushed to the correct branch.

File Structure

  • Correct index.html exists.
  • Files are in the publishing folder.
  • CSS, JavaScript, and images have correct paths.

Website Quality

  • Pages have meaningful titles.
  • Images have appropriate alt text.
  • Navigation links work.

Responsive Design

  • Layout works on mobile screens.
  • Text is readable.
  • Buttons are easy to use.

03 · ENABLE GITHUB PAGES

Publish Your Website

  1. Open your GitHub repository.
  2. Go to Settings.
  3. Open the Pages section.
  4. Select Deploy from a branch if using branch-based publishing.
  5. Choose the correct branch, usually main.
  6. Choose the publishing folder, usually /(root).
  7. Click Save.
  8. Wait for GitHub Pages to finish deploying.

Important: Check the deployment status and the published URL in the Pages settings.

04 · AFTER DEPLOYMENT

Test the Live Website

Open the URL

Visit the published GitHub Pages address and make sure the homepage loads.

Test Navigation

Open each important page and check the navigation links.

Check Assets

Confirm that images, CSS, fonts, and JavaScript load correctly.

Test Different Screens

Check the website on desktop and mobile screen sizes.

05 · ACCESSIBILITY

Accessibility and Lighthouse

Accessibility helps more people use a website, including people who rely on assistive technologies.

  • Use semantic HTML elements such as header, nav, main, and footer.
  • Add meaningful alt text to informative images.
  • Make sure text has sufficient contrast against its background.
  • Make interactive elements usable with a keyboard.
  • Use clear labels for form controls.
  • Run a Lighthouse accessibility audit and review its results.
Homework target:

Accessibility score of at least 90 in Lighthouse, with a screenshot of the result.

A high score is useful, but it does not replace checking accessibility manually.

06 · COMMON DEPLOYMENT PROBLEMS

What Should You Check?

404 Not Found

Check the homepage filename and publishing folder.

Old Content

Check whether deployment finished, then refresh the browser.

Missing Images

Check image paths, filenames, and letter capitalization.

Broken Styles

Check stylesheet paths, especially when using a project-site URL.

Topic 02 — Native Elements Over Div

Use the right HTML element for the right purpose. Native elements provide accessibility features automatically.

BATSUREN ANAR · STUDENT ID: 202637018

Why Native HTML Elements Matter

HTML elements have built-in meanings and behaviors. For example, a button is designed for actions, while a link is designed for navigation.

A clickable div may look like a button, but it does not automatically behave like one. It needs extra code to support keyboard users and assistive technologies.

Two Important Rules

Use <button> for actions

Use a button when the user needs to perform an action, such as opening a menu, submitting a form, or showing a message.

Use <a href> for navigation

Use a link when the user needs to move to another page or a different location.

Avoid clickable divs

Do not use a div or span as an interactive element when a native button or link can do the job.

<div onclick> vs. <button>

Both examples below can respond to a mouse click. However, their keyboard and accessibility behavior is different.

Clickable div

Click me

Problems:

  • Cannot be focused with Tab by default.
  • Enter and Space do not activate it automatically.
  • No accessible button role is assigned.
  • Screen readers may announce it as a generic group.
Click the div to test it.

Native button

Benefits:

  • Focusable with the Tab key automatically.
  • Enter and Space both activate it.
  • The button role is provided automatically.
  • Screen readers announce it as a button.
Click or keyboard-activate the button.

Code Comparison

Incorrect approach for an action

<div onclick="doSomething()"
     style="cursor:pointer">
    Click me
</div>

This div responds to a mouse click, but it does not automatically support keyboard interaction or a button role.

Recommended approach

<button type="button"
        onclick="doSomething()">
    Click me
</button>

The native button already supports keyboard focus, Enter, Space, and the button role.

What If a Custom Div Is Necessary?

Sometimes a custom interactive element is unavoidable. In that case, it needs additional accessibility features. 

<div
    role="button"
    tabindex="0"
    aria-label="View project details"
    onclick="openProject()"
    onkeydown="handleKey(event)">
    View project
</div>

function handleKey(e) {
    if (e.key === "Enter" || e.key === " ") {
        openProject();
        e.preventDefault();
    }
}

This example adds a button role, keyboard focus, and keyboard event handling. However, using a native button is still simpler and more reliable.

Quick Quiz

A designer makes a clickable div that opens a modal. What is missing for accessibility?

Choose an answer to check your understanding.

Answer explanation

Div elements do not receive keyboard focus or a button role by default. Use a native button instead, or add role="button", tabindex="0", and a keydown handler for Enter and Space.

Without these features, keyboard users and screen reader users may not be able to activate the control.

Remember

  • Use <button> for actions.
  • Use <a href> for navigation.
  • Do not use a div or span as an interactive element.
  • Native elements already include useful accessibility behavior.
  • Custom controls need keyboard support and the correct role.

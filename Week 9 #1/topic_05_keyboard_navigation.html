Week 9 #1 · Topic 05

Keyboard Navigation

Every interactive part of a website should work without a mouse. Keyboard accessibility allows users to navigate links, buttons, menus, forms, and other controls using the keyboard.

01 · The concept

Keyboard Navigation — It Must ALL Work

Some users cannot use a mouse because of motor disabilities, limited arm mobility, or personal preference. A website must allow them to reach and operate every interactive element using only a keyboard.

Quick test: Put your mouse away. Open your website and navigate using only the keyboard. Can you reach every link and button?

Keyboard accessibility is part of the WCAG Operable principle. Users must be able to operate the interface without a mouse.

02 · Keyboard controls

Know These Keys

Tab
Move to the next focusable element.
Shift + Tab
Move to the previous focusable element.
Enter
Activate links and buttons.
Space
Check or uncheck boxes; activate buttons.
↑ ↓ ← →
Navigate menus, radio groups, and sliders.
Escape
Close modal dialogs and dropdown menus.
03 · Focus and tab order

What Is Keyboard Focus?

Focus identifies which interactive element will receive keyboard input. Pressing Tab moves focus through the page in its natural document order.

Click the first button, then press Tab repeatedly. Watch the visible focus outline move through the controls.

Important: A visible focus indicator helps keyboard users understand which element is currently selected. Do not remove focus outlines without providing a clear replacement.
04 · tabindex

Making Custom Elements Focusable

The tabindex attribute controls whether an element can receive keyboard focus and how it participates in the Tab order.

tabindex="0"

Natural Tab order

Adds an element to the normal keyboard Tab order at its natural position in the document. 

<div
    role="button"
    tabindex="0">
    View project
</div>

Use for custom interactive elements when a native button or link is not suitable.

tabindex="-1"

Programmatic focus

Allows an element to receive focus through JavaScript, but it is not reached through normal Tab navigation. 

<h2 id="dialog-title"
    tabindex="-1">
    Project details
</h2>

document.getElementById(
    "dialog-title"
).focus();

Useful for focus management, such as moving focus into a dialog.

tabindex="1+"

Avoid positive values

Positive tabindex values can disrupt the natural order and make keyboard navigation unpredictable. 

<button tabindex="5">
    Button
</button>

Avoid positive tabindex values. Keep the natural document order instead.

role

Give custom elements meaning

When making a custom element focusable, give it the correct ARIA role so assistive technologies understand what it does. 

<div
    role="button"
    tabindex="0">
    Open project
</div>

Focusability alone does not communicate the element's meaning.

05 · Custom keyboard interaction

Making a Custom Button Work

A custom element with role="button" and tabindex="0" can receive keyboard focus. However, it also needs keyboard event handling.

This project card is a custom button. Try focusing it with Tab and activating it with Enter or Space.

My Final Project A custom interactive project card

Waiting for keyboard or mouse activation. 

<div
    role="button"
    tabindex="0"
    aria-label="View project details"
    onclick="openProject()"
    onkeydown="handleKey(event)">
    My Final Project
</div>

function handleKey(e) {
    if (e.key === "Enter" || e.key === " ") {
        openProject();
        e.preventDefault();
    }
}
Important: Pressing Space normally scrolls the page. Use e.preventDefault() when Space activates a custom button.

Whenever possible, use a real <button> instead. Native buttons already support keyboard activation without custom JavaScript.

10 · Summary

What We Learned

  • Tab: Moves to the next focusable element.
  • Shift + Tab: Moves to the previous focusable element.
  • Enter and Space: Activate links and buttons.
  • Arrow keys: Navigate menus, radio groups, and sliders.
  • Escape: Closes modal dialogs and dropdown menus.
  • tabindex="0": Adds an element to the natural Tab order.
  • tabindex="-1": Allows programmatic focus without normal Tab navigation.
  • Positive tabindex: Avoid because it disrupts the natural order.
  • role: Gives custom interactive elements semantic meaning.
Main takeaway: A website is not fully accessible if users cannot operate it without a mouse.

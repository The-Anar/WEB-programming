02 · ACCESSIBILITY FIXES

What Was Improved?

1. Form labels

Each input has a visible label connected through the for and id attributes. 

<label for="email">
  Email address
</label>

<input id="email" type="email">

2. Accessible search button

The search icon has an accessible name so a screen reader can announce its purpose. 

<button
  type="button"
  aria-label="Search">
  🔍
</button>

3. Error descriptions

The aria-describedby attribute connects each input to its error message. 

<input
  id="password"
  aria-describedby="passwordError">

4. Keyboard focus

Visible focus indicators help keyboard users understand which control is currently selected. 

button:focus-visible{
  outline:3px solid purple;
  outline-offset:4px;
}

03 · TEAM

About Our Team

We believe accessible websites should be easy to use for everyone. Good labels, clear instructions, and keyboard support make websites more inclusive.

04 · LIGHTHOUSE CHECKLIST

What Should You Test?

  • Inputs have associated labels.
  • Buttons have accessible names.
  • Error messages are connected to their inputs.
  • Text has sufficient color contrast.
  • All controls work using a keyboard.
  • Focus indicators are visible.
  • Links describe their destination or purpose.

Run Lighthouse in Chrome DevTools and review its Accessibility report. Automated testing does not replace manual keyboard and screen-reader testing.

05 · WHAT WE LEARNED

Exercise Summary

  • Use labels for form inputs.
  • Give icon-only buttons accessible names.
  • Connect validation messages to their inputs.
  • Use clear error messages.
  • Make forms usable with a keyboard.
  • Use Lighthouse to identify common accessibility issues.

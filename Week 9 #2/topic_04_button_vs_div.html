The <button> vs <div> Problem

A clickable div may look like a button, but it does not automatically provide the keyboard and accessibility features of a real HTML button.

BATSUREN ANAR · STUDENT ID: 202637018

THE WRONG APPROACH

Using a Div as a Button

✗ Non-semantic example
<div class="btn" onclick="submitForm()">
  Submit
</div>

A normal div is not keyboard-focusable and does not automatically behave like a button.

  • Cannot normally be reached using Tab.
  • Does not automatically respond to Enter or Space.
  • Screen readers do not identify it as a button.
  • Does not support the native disabled state.

THE BETTER APPROACH

Using a Real HTML Button

✓ Semantic example
<button type="button" onclick="submitForm()">
  Submit
</button>

The browser automatically provides keyboard support, button semantics, and a native disabled attribute.

  • Can be reached using Tab.
  • Enter and Space activate it.
  • Screen readers announce its button role.
  • Supports the disabled attribute.

NATIVE BUTTON FEATURES

What a Real Button Gives You for Free

FeatureNative button behavior
Keyboard focusAutomatically included in the Tab order.
Enter and SpaceBoth keys activate the button.
Accessible roleScreen readers identify it as a button.
Disabled stateThe disabled attribute prevents activation and focus.
Focus indicatorBrowsers provide a visible focus indicator by default.

WHEN A DIV IS NECESSARY

Custom Interactive Elements

Sometimes developers build custom widgets that do not have a suitable native HTML element. In that situation, a div may need additional accessibility behavior. 

<div
  role="button"
  tabindex="0"
  onkeydown="handleKeyboard(event)"
>
  Custom widget
</div>

The developer must also implement keyboard activation, focus styling, and disabled behavior correctly. A native button is usually the simpler and safer choice.

IMPORTANT HTML RULE

Button or Link?

Use <button> for actions

Examples: submitting a form, opening a dialog, saving information, or changing a setting.

Use <a href> for navigation

Examples: opening another page, visiting a website, or jumping to a section.

Remember: Use type="button" for buttons inside forms when they should not submit the form. The default type of a button inside a form is submit.

KEY POINTS

What We Learned

  • Use native buttons for actions.
  • Use links for navigation.
  • A clickable div is not automatically keyboard-accessible.
  • Native buttons provide built-in keyboard and accessibility support.
  • Do not remove focus indicators without providing a visible replacement.
  • Use type="button" when a button should not submit a form.

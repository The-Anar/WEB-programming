Lighthouse Accessibility Audit

Google Lighthouse is a tool that checks different aspects of a website, including accessibility. It helps developers identify problems and improve the experience for users.

INTRODUCTION

What Is Lighthouse?

Lighthouse is an automated website auditing tool available in Chrome DevTools. It can evaluate accessibility, performance, best practices, and SEO.

For this topic, we focus on the Accessibility category. It checks for common problems that may prevent people from using a website effectively.

Lighthouse is useful for finding issues, but automated testing cannot detect every accessibility problem.

STEP-BY-STEP GUIDE

How to Run an Accessibility Audit

  1. Open the website you want to test in Google Chrome.
  2. Press F12 to open Chrome DevTools.
  3. Select the Lighthouse tab.
  4. Choose the Accessibility category.
  5. Select the device mode you want to test.
  6. Click Analyze page load or the available audit button.
  7. Wait for Lighthouse to generate the report.
  8. Expand failed audit items to see details and recommendations.
Remember:

Test the actual page you want to evaluate. Different pages on the same website can have different accessibility issues.

UNDERSTANDING THE SCORE

Lighthouse Accessibility Scores

Lighthouse displays an accessibility score from 0 to 100. The following ranges are commonly used to interpret the result.

90–100
Good
50–89
Needs work
0–49
Poor

These ranges are score interpretations, not separate WCAG conformance levels. A high Lighthouse score does not mean a website is fully accessible.

COMMON PROBLEMS

What Should You Fix?

ProblemPossible solution
Images missing alt text Add meaningful alternative text or use an empty alt attribute for decorative images.
Low color contrast Choose foreground and background colors with sufficient contrast.
Buttons without accessible names Add clear visible text or an appropriate accessible name.
Form fields without labels Connect each input to a descriptive label.
Links without meaningful text Use link text that explains its purpose or destination.
Missing document language Set the correct language using the HTML lang attribute.

IMPORTANT LIMITATION

Why a Score of 100 Is Not Enough

Lighthouse performs automated checks. Some accessibility problems require a person to evaluate the website.

  • It cannot reliably judge whether alt text accurately describes an image.
  • It cannot fully understand whether the reading order makes sense.
  • It cannot guarantee that keyboard users will never encounter a keyboard trap.
  • It cannot determine whether instructions and language are easy to understand.
  • It cannot fully evaluate the experience of using a screen reader.

A score of 100 means the page passed the automated checks that Lighthouse performed. It does not prove complete WCAG conformance.

MANUAL TESTING

Test with Real Assistive Technologies

Keyboard testing

Navigate the entire page using Tab, Shift + Tab, Enter, Space, and arrow keys where appropriate.

NVDA

A free screen reader for Windows. It helps developers understand how a website is announced to screen-reader users.

VoiceOver

Apple's built-in screen reader for macOS and iOS. Use it to test navigation and spoken content.

JAWS

A widely used commercial screen reader for Windows that can be used for additional compatibility testing.

KEY POINTS

What We Learned

  • Lighthouse can identify many common accessibility problems.
  • Chrome DevTools provides an Accessibility audit.
  • Scores from 90 to 100 are generally considered good.
  • Fix missing alt text, contrast issues, and inaccessible labels.
  • A score of 100 does not guarantee full accessibility.
  • Manual keyboard and screen-reader testing are also important.
  • Accessibility should be considered throughout development, not only at the end.

Exercise 01 — Run Lighthouse & Fix the Page

In this exercise, I tested my portfolio using Lighthouse and applied several changes to improve how the page loads.

BATSUREN ANAR · STUDENT ID: 202637018

01. Before Optimization

First, I ran Lighthouse on my portfolio homepage using mobile emulation and Slow 4G throttling.

02. Optimizations Applied

I made three changes to the website after checking the page structure and its loading behavior.

01 — Delayed YouTube Loading

I removed the automatic YouTube player loading. Now, the iframe loads only when a visitor opens Music Corner.

02 — Deferred JavaScript

I added the defer attribute to music-player.js so the browser can finish parsing the HTML before executing it.

03 — Removed Duplicate CSS

I removed one repeated prefers-reduced-motion rule while keeping the remaining accessibility rule.

03. After Optimization

After applying the changes, I deployed the updated website and ran Lighthouse again with the same settings.

Performance 100 → 100
First Contentful Paint 1.1 s → 1.1 s
Largest Contentful Paint 1.1 s → 1.1 s
Total Blocking Time 0 ms → 0 ms
Cumulative Layout Shift 0 → 0
Speed Index 1.8 s → 1.5 s

04. What I Learned

I learned that delaying unnecessary third-party content, using deferred scripts, and removing duplicate CSS can help keep a webpage more efficient. My Lighthouse Performance score remained at 100, while the Speed Index improved from 1.8 seconds to 1.5 seconds in these tests.

Test environment: Lighthouse 13.5.0, Moto G Power emulation, Slow 4G throttling, and the deployed portfolio homepage. Lighthouse results may vary slightly between runs.

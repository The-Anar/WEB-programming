Exercise 03 — Add defer to Scripts

Learn how the defer attribute improves page loading by allowing HTML parsing and JavaScript downloading to happen at the same time.

BATSUREN ANAR · STUDENT ID: 202637018

1. Normal Script vs. Defer

Normal Script

The browser stops parsing HTML while it downloads and executes the JavaScript. 

<script src="app.js"></script>

This can delay the page from being displayed.

Deferred Script

The browser downloads JavaScript while continuing to parse the HTML. It executes the script after HTML parsing is complete. 

<script src="app.js" defer></script>

This avoids blocking HTML parsing.

Async Script

The browser downloads JavaScript in parallel and executes it as soon as it is ready. 

<script src="analytics.js" async></script>

Execution order is not guaranteed.

2. How Defer Works

  1. The browser starts reading the HTML document.
  2. The browser downloads the deferred JavaScript in parallel.
  3. HTML parsing continues without waiting for the script.
  4. After HTML parsing finishes, the deferred script executes.

Deferred scripts execute in the order they appear in the HTML document. 

<head>
    <script src="first.js" defer></script>
    <script src="second.js" defer></script>
</head>

first.js executes before second.js, even if second.js finishes downloading first.

4. Best Practice

For most external JavaScript files, use defer in the HTML head. This lets the browser parse the page while downloading scripts in the background. 

<head>
    <script src="app.js" defer></script>
</head>

JavaScript files using type="module" are deferred automatically by the browser.

Use async for independent scripts, such as analytics, when execution order does not matter.

5. What I Learned

I learned that normal scripts can block HTML parsing, while deferred scripts download in parallel and execute after the HTML document has been parsed. I also learned that defer preserves script order, whereas async does not guarantee execution order.

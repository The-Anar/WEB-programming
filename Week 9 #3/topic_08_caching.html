Caching

Make websites faster by reusing stored files instead of downloading the same resources every time.

BATSUREN ANAR · STUDENT ID: 202637018

01 — What Is Caching?

Caching allows the browser to store files and reuse them instead of downloading them again on every visit. This can reduce unnecessary network requests and help websites load faster.

The server controls caching behavior through HTTP Cache-Control headers.

02 — Cache-Control Headers

Cache-Control headers are set by the server. They tell the browser how long a resource can be stored and reused.

public, max-age=31536000, immutable 1 year

For versioned CSS and JavaScript files, and fonts.

public, max-age=3600 1 hour

For content that changes sometimes.

no-cache Check with the server first

The browser must check whether the resource has changed before reusing it. Commonly used for HTML.

no-store Never store

Used for private data that should not be stored. 

Cache-Control: public, max-age=31536000, immutable
Cache-Control: public, max-age=3600
Cache-Control: no-cache
Cache-Control: no-store

03 — 304 Not Modified

A 304 Not Modified response means the cached file has not changed. The browser can reuse its stored copy instead of downloading the entire file again.

1
First visit

The server sends the file along with an ETag (a fingerprint) or a Last-Modified date.

2
Browser checks again

When the cached copy expires, the browser asks the server whether the file has changed, using a request header such as If-None-Match.

3
304 Not Modified

If the file has not changed, the server responds with 304 and no response body. The browser reuses its cached copy.

How to check: Open DevTools → Network. A reused file may show (memory cache), (disk cache), or a 304 status.

04 — Cache Busting

Cache busting prevents the browser from using an old version of a file after the file has been updated.

One common method is to include a content hash in the filename. 

<link rel="stylesheet" href="styles.a3f9c2b1.css">

<script src="app.d8e4f2a9.js" defer></script>
1
Change the file

The file's content is updated.

2
The hash changes

The updated file receives a different filename.

3
New URL

Because the URL is different, the browser downloads the new version.

Build tools can automatically add these hashes to filenames.

05 — Recommended Cache Duration

Different resources should have different caching durations depending on how often they change.

Resource Cache for
HTML no-cache / short — users must get new HTML
CSS & JS with a hash 1 year, immutable
Images 1 month – 1 year
Fonts 1 year

06 — GitHub Pages Limitation

On GitHub Pages, you cannot set these Cache-Control headers yourself.

Important: GitHub Pages sends max-age=600 (10 minutes) for every file.

This means you cannot directly configure different cache durations for HTML, CSS, JavaScript, images, and fonts on GitHub Pages.
